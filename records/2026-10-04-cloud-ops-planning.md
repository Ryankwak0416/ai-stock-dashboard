# 클라우드 운영 계획 기록 (2026-10-04)

> 공개 저장소에 두는 기록이라 업무명, 예약 작업 이름, 회사 정보는 뺐다.

## 스토리: 왜 이렇게 정했나

로컬 PC에서 하던 작업을 클라우드 세션으로 가져와 이어서 할 수 있는지 묻는 데서 시작했다.
알아보니 클라우드 세션은 GitHub에 올린 것만 볼 수 있다. 세션은 임시 컴퓨터에서 돌아서 끝나면 사라지고, PC 폴더와 프로그램에는 닿지 못한다.
클라우드 세션과 예약 작업도 앱, Cowork와 같은 구독 사용량(5시간 한도, 주간 한도)에서 빠지고, 별도 요금은 없다.

현황을 보니 자동 작업 상당수가 이미 클라우드 예약 작업으로 돌고 있었다.
그중 일부는 PC 파일이 필요해서 꺼져 있었고, 켜진 것 가운데 2개는 PC 파일이 필요해 보이는데도 '성공'으로 기록되고 있었다.
'성공'은 실행이 끝났다는 뜻일 뿐 결과물이 생겼다는 뜻이 아니므로, 따로 확인하기로 했다.

그래서 다음과 같이 정했다. 큰 데이터(도면, 사진, 원본 파일, 개인 서류)는 클라우드에 두지 않고 PC에 둔다.
Claude 운영에 관한 작은 정보(공통 규칙, 예약 작업 지시문, PC별 상태, 인계 메모)만 클라우드의 '운영 본부'에 둔다.
각 PC와 클라우드는 이 본부를 거쳐서 소통한다.

이 방향으로 계획서를 쓰고, 별도 에이전트에게 독립 검토를 맡겨 지적 10건을 반영했다.
주로 바뀐 것은 네 가지다. Cowork는 자동 실행이 보장되지 않아 시험해 보기로 했고, 본부 위치는 GitHub와 드라이브를 비교해 고르기로 했다.
각 PC에서 직접 점검하는 단계를 넣었고, 본부 구조는 파일 몇 개로 줄였다.

지금은 본부 위치(비공개 GitHub 또는 드라이브 폴더)와 이름을 정하는 단계에서 멈춰 있다.

## 히스토리: 언제 무엇을 했나

모두 2026-10-04에 한 일이며, 한 순서대로 적었다.

| 순서 | 한 일 | 결과 |
| --- | --- | --- |
| 1 | 로컬 작업을 클라우드로 가져올 수 있는지 확인 | GitHub에 푸시하면 가능하다. 비밀값과 PC 파일은 따로 다뤄야 한다 |
| 2 | GitHub 용량과 파일 옮기는 방법 확인 | 파일 하나 100MB 제한, 저장소는 1GB 이하 권장. 공개 저장소라 회사 문서는 올리면 안 된다 |
| 3 | 클라우드 예약 작업 현황 조회 | 18개 중 10개가 켜져 있고, 그중 2개는 확인이 필요하다 |
| 4 | 예약 작업 분석은 나중으로 미룸 | 앱에 작업 카드로 저장했다 |
| 5 | 연계 기준 개념도 작성 | 비공개 아티팩트로 게시했다 |
| 6 | 클라우드 사용 요금 확인 | 같은 사용량 한도를 쓰고 별도 요금은 없다(공식 문서) |
| 7 | 공통 운영 계획서 작성 | 7개 절과 소통 흐름 그림을 넣었다 |
| 8 | 계획서 독립 검토 | 지적 10건을 반영했다 |
| 9 | 실행 소요 시간 추정 | 손이 가는 시간 6~8시간, 기간은 준비 1주와 시험 운영 2주 |
| 10 | 이 기록 커밋 | 공개 저장소라 민감 정보를 뺐다 |

대화 중에 바로잡은 것:

- 켜진 예약 작업을 처음에 11개라고 했지만 다시 세어 보니 10개였다. 개념도와 작업 카드를 고쳤다.
- 드라이브는 변경 기록이 남지 않는다고 했지만, 파일 단위 버전 기록이 있다(보관 기간 제한). 계획서의 비교표에 바르게 적었다.
